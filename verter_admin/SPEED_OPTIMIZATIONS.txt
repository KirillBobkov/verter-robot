ОПТИМИЗАЦИИ СКОРОСТИ РАСПОЗНАВАНИЯ (RPi4)
===========================================

Изменено в speech_to_text_node.py:

1. АСИНХРОННОЕ РАСПОЗНАВАНИЕ (главное!)
   - Распознавание запускается в отдельном потоке
   - Audio callback НЕ блокируется
   - Результат: нет input overflow

2. БЫСТРЫЙ ТРИГГЕР ПАУЗЫ
   - Было: SILENCE_CHUNKS = 6 (600ms паузы)
   - Стало: SILENCE_CHUNKS = 4 (400ms паузы)
   - Результат: на 200ms быстрее начинается распознавание

3. ОПТИМИЗАЦИЯ ONNX
   - NUM_THREADS = 1 (лучше для ARM Cortex-A72)
   - graph_optimization_level = ORT_ENABLE_ALL
   - enable_cpu_mem_arena = True
   - Результат: быстрее inference

4. TIMING LOGS
   - Логируется время feature extraction
   - Логируется время inference
   - Можно видеть где узкое место

ОЖИДАЕМЫЙ РЕЗУЛЬТАТ:
- Было: ~1.5-2s задержка + input overflow
- Стало: ~0.75-1.1s задержка БЕЗ overflow

МОНИТОРИНГ:
После каждого распознавания будет лог вида:
  🎤 Распознано: 'текст'
  ⏱️  Timing: feature=250ms, inference=380ms, total=630ms

Норма для коротких фраз:
  - feature: 150-300ms
  - inference: 200-400ms
  - total: 400-700ms

Норма для длинных фраз:
  - feature: 300-500ms
  - inference: 300-600ms
  - total: 700-1100ms

ЕСЛИ МЕДЛЕННО:
- inference > 600ms → попробуй NUM_THREADS = 2
- feature > 500ms → фраза слишком длинная или CPU перегружен
- Есть overflow → проверь что запущена новая версия

ЕСЛИ РЕЖЕТ ФРАЗЫ:
- Увеличь SILENCE_CHUNKS до 5 или 6

ТЕСТИРОВАНИЕ:
1. Запусти: ros2 launch verter_admin admin.launch.py
2. Говори короткие фразы с паузами 0.5-1 секунда
3. Смотри логи - не должно быть "input overflow"
4. Смотри timing - должно быть <1000ms для коротких фраз
