# Одометрия для робота Verter

## 📚 Что такое одометрия? (для новичков)

### Простым языком

Представь, что ты играешь в игру с закрытыми глазами: ты стоишь на месте, и кто-то говорит тебе "сделай 5 шагов вперед, поверни налево на 90 градусов, сделай еще 3 шага". Даже с закрытыми глазами ты можешь вычислить где ты окажешься относительно начальной точки.

**Одометрия** делает то же самое для робота - вычисляет где он находится, основываясь на том, как он двигался.

### Аналогия из программирования (Java)

Если ты работал с сервлетами в Java:
- **Топики** = очереди сообщений (как JMS/Kafka)
- **Ноды** = микросервисы
- **Callback функции** = обработчики событий (как @EventListener в Spring)
- **TF (Transform)** = система координат (как работа с координатами на карте)

## 🏗️ Архитектура одометрии

```
┌─────────────────────────────────────────────────────────────┐
│                     СИСТЕМА ОДОМЕТРИИ                        │
└─────────────────────────────────────────────────────────────┘

ВХОДНЫЕ ДАННЫЕ (Subscribe):
┌──────────────────┐
│   /cmd_vel       │ ──► Команды скорости от Nav2
│  (Twist)         │     linear.x: скорость вперед/назад
└──────────────────┘     angular.z: скорость поворота


ОБРАБОТКА (odometry_node):
┌────────────────────────────────────────────────────┐
│  1. Получить команду скорости (vx, vth)            │
│  2. Вычислить dt (время с прошлого обновления)     │
│  3. ИНТЕГРИРОВАТЬ: новая_позиция = старая + v*dt   │
│  4. Обновить состояние (x, y, theta)               │
│  5. Опубликовать результат                         │
└────────────────────────────────────────────────────┘


ВЫХОДНЫЕ ДАННЫЕ (Publish):
┌──────────────────┐
│   /odom          │ ──► Полная информация об одометрии
│  (Odometry)      │     - Позиция (x, y, theta)
└──────────────────┘     - Скорость (vx, vth)

┌──────────────────┐
│   /tf            │ ──► Трансформация odom -> base_link
│ (TransformStamped)     (КРИТИЧНО для Nav2!)
└──────────────────┘

┌──────────────────┐
│ /verter_commands │ ──► Команды для текущего chassis_node
│  (String)        │     CHASSIS:FRONT, CHASSIS:STOP и т.д.
└──────────────────┘
```

## 🔑 Ключевые концепции ROS2

### 1. Топики (Topics)

**Что это?** Каналы связи между нодами.

**Аналогия из Java:**
- Kafka topics
- JMS queues
- WebSocket channels

**Пример:**
```python
# Публикация (отправка данных в топик)
publisher = self.create_publisher(Odometry, '/odom', 10)
publisher.publish(message)

# Подписка (получение данных из топика)
subscriber = self.create_subscription(Twist, '/cmd_vel', callback, 10)
```

### 2. Сообщения (Messages)

**Что это?** Структуры данных, передаваемые в топиках.

**Аналогия из Java:**
- DTO (Data Transfer Objects)
- Protocol Buffers
- JSON объекты в REST API

**Основные типы сообщений:**

#### Twist (geometry_msgs/Twist)
Команды скорости для робота:
```python
msg = Twist()
msg.linear.x = 0.5   # Скорость вперед: 0.5 м/с
msg.angular.z = 1.0  # Поворот: 1.0 рад/с
```

#### Odometry (nav_msgs/Odometry)
Информация о положении робота:
```python
odom = Odometry()
odom.pose.pose.position.x = 1.5      # X координата (метры)
odom.pose.pose.position.y = 2.0      # Y координата (метры)
odom.pose.pose.orientation = quat    # Ориентация (кватернион)
odom.twist.twist.linear.x = 0.5      # Текущая скорость
```

### 3. TF (Transform Framework)

**Что это?** Система координат в ROS2.

**Зачем?** Каждая часть робота (сенсоры, колеса, корпус) имеет свою систему координат. TF показывает как они связаны.

**Аналогия из жизни:**
Представь матрешку - каждая кукла внутри другой. TF говорит "где маленькая кукла относительно большой".

**Основные системы координат (frames):**

```
map          ──► Глобальная карта мира (появится при использовании SLAM)
 └─ odom     ──► Начальная точка робота (откуда стартовал)
     └─ base_link  ──► Центр робота (его тело)
         ├─ laser  ──► Где находится лидар
         ├─ camera ──► Где находится камера
         └─ wheels ──► Где находятся колеса
```

**Пример:**
```python
# Публикация трансформации "odom -> base_link"
transform = TransformStamped()
transform.header.frame_id = 'odom'        # Откуда
transform.child_frame_id = 'base_link'    # Куда
transform.transform.translation.x = 1.5   # Сдвиг по X
transform.transform.rotation = quaternion # Поворот
```

## 📊 Как работает интегрирование скорости?

### Математика (упрощенно)

Если робот едет со скоростью `v` м/с в течение `t` секунд, то он проедет:
```
расстояние = скорость × время
distance = v × t
```

В коде:
```python
# Временной интервал
dt = current_time - last_time  # Например, 0.02 сек (50 Гц)

# Изменение угла (поворот)
delta_theta = angular_velocity * dt

# Изменение позиции (с учетом текущего угла!)
delta_x = linear_velocity * dt * cos(current_angle)
delta_y = linear_velocity * dt * sin(current_angle)

# Обновление позиции
new_x = old_x + delta_x
new_y = old_y + delta_y
new_theta = old_theta + delta_theta
```

### Почему cos и sin?

Робот движется в **своей** системе координат (вперед), но мы хотим знать позицию в **глобальной** системе координат.

```
Если робот смотрит на Север и едет вперед:
  - X увеличивается (cos(0°) = 1)
  - Y не меняется (sin(0°) = 0)

Если робот смотрит на Восток и едет вперед:
  - X не меняется (cos(90°) = 0)
  - Y увеличивается (sin(90°) = 1)
```

## 🚀 Как использовать

### Запуск ноды одометрии

```bash
# Вариант 1: Запуск напрямую
ros2 run verter_admin odometry_node

# Вариант 2: Через launch файл (рекомендуется)
ros2 launch verter_admin odometry.launch.py
```

### Проверка что нода работает

```bash
# Список активных нод
ros2 node list
# Должна быть: /odometry_node

# Список топиков
ros2 topic list
# Должны быть: /odom, /cmd_vel, /tf, /verter_commands

# Проверка публикации одометрии
ros2 topic echo /odom

# Проверка TF трансформаций
ros2 run tf2_ros tf2_echo odom base_link
```

### Тестирование с ручным управлением

```bash
# Отправить команду скорости
ros2 topic pub /cmd_vel geometry_msgs/Twist \
  "{linear: {x: 0.2, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}" \
  --once

# Остановить робота
ros2 topic pub /cmd_vel geometry_msgs/Twist \
  "{linear: {x: 0.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}" \
  --once
```

## 🔧 Настройка под ваш робот

### Важные параметры в `odometry_node.py`

```python
# Максимальные скорости (строки ~51-52)
self.max_linear_velocity = 0.5    # Максимальная скорость вперед (м/с)
self.max_angular_velocity = 1.0   # Максимальная скорость поворота (рад/с)

# Коэффициенты калибровки (строки ~55-56)
self.linear_scale = 1.0   # Если робот едет слишком быстро, уменьши
self.angular_scale = 1.0  # Если робот поворачивает слишком быстро, уменьши

# Частота обновления (строка ~128)
update_frequency = 50.0  # Гц (50 раз в секунду)
```

### Калибровка одометрии

**Проблема:** Робот проехал 1 метр, но одометрия показывает 1.2 метра.

**Решение:**
1. Измерь реальное расстояние
2. Сравни с одометрией
3. Вычисли коэффициент: `scale = реальное / одометрия`
4. Установи `self.linear_scale = scale`

**Пример:**
```python
# Робот проехал реально 1.0 м, одометрия показала 1.2 м
self.linear_scale = 1.0 / 1.2  # = 0.833
```

## 💡 Частые вопросы

### Q: Зачем нужна одометрия если у нас есть датчики расстояния?

A: Датчики расстояния говорят "что вокруг робота", одометрия говорит "где робот находится". Для навигации нужно и то и другое.

### Q: Почему одометрия "дрейфует" (становится неточной)?

A: Одометрия основана на интегрировании - ошибки накапливаются со временем. Для точной навигации нужна **локализация** (например, AMCL с использованием карты и лидара).

### Q: Можно ли использовать GPS вместо одометрии?

A: GPS работает только на улице и недостаточно точен для робота внутри помещения (точность ~3-5 метров). Одометрия дает точность в сантиметрах.

### Q: Что такое кватернион и зачем он нужен?

A: Кватернион - математический способ представления поворота в 3D. В ROS2 используется вместо углов Эйлера (roll, pitch, yaw) потому что:
- Нет проблемы "gimbal lock"
- Более эффективен для интерполяции
- Стандарт в робототехнике
