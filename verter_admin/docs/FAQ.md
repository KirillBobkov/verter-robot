# FAQ - Часто задаваемые вопросы

## Вопрос: Что такое семантическое картографирование?

**Короткий ответ:** Робот понимает ЧТО он видит, а не только ГДЕ препятствие.

**Подробнее:**

### Обычная карта (occupancy grid):
```
┌─────────────────┐
│ █████           │  █ = Препятствие
│ █   █           │  ░ = Свободно
│ █   █  ░░░      │  ? = Неизвестно
│     █  ░░░      │
└─────────────────┘

Робот знает: "В координатах (2,3) есть препятствие"
```

### Семантическая карта:
```
┌─────────────────┐
│ 🧱СТЕНА         │
│ 🧱  🚪ДВЕРЬ     │
│ 🧱  🚪  👤ЧЕЛОВЕК│
│     🚪  🪑СТУЛ  │
└─────────────────┘

Робот знает: "В координатах (2,3) находится дверь,
              в (5,3) стоит человек (временное препятствие),
              в (7,4) стоит стул (можно объехать)"
```

**Применение:**
1. **Умные waypoints:** "Поставь waypoint перед дверью кабинета врача"
2. **Фильтрация динамики:** Люди не добавляются на статическую карту
3. **Адаптивное поведение:** Рядом с человеком - ехать медленнее и осторожнее
4. **Голосовые команды:** "Найди дверь в операционную"

**Для реализации нужно:**
- Камера (RGB или RGB-D)
- YOLOv8 или подобная нейросеть для детекции объектов
- Jetson Orin Nano идеален для этого (GPU inference)

**Когда добавлять:** После реализации базовой навигации (Фаза 5+)

## Вопрос: Слепая зона сзади - это проблема?

**Короткий ответ:** Это ограничение, но решаемое.

**Текущая конфигурация:**
- Лидар: 180° спереди (-90° до +90°)
- Ультразвуковые: ~150° спереди (-76° до +76°)
- **Итого:** Задние ~180° не имеют сенсоров

**Почему это не критично:**

### 1. Дифференциальный привод = преимущественно вперед
Робот с двумя ведущими колесами спереди:
- Основное движение - вперед
- Движение назад - редкое исключение
- Повороты на месте - в любую сторону

### 2. Nav2 оптимизирован под forward navigation
```yaml
# Конфигурация контроллера
FollowPath:
  allow_reversing: false  # Запретить движение задом
  rotate_to_heading: true # Повернуться перед движением
```

**Как это работает:**
1. Робот планирует путь
2. Если нужно ехать "назад", робот сначала поворачивается на 180°
3. Затем едет вперед (где есть сенсоры!)
4. На месте назначения поворачивается в нужную ориентацию

### 3. Одометрия и IMU знают что сзади
Даже без сенсоров робот помнит:
- Карту построенную раньше
- Свое положение (одометрия + IMU)
- Что было сзади 1-2 секунды назад

### 4. Когда возникнет проблема?

**Проблемный сценарий:**
```
Робот едет вперед → Человек идет сзади → Робот резко тормозит
                                       ↓
                        Человек может не успеть среагировать
```

**Реальность в больнице/торговом центре:**
- Робот движется медленно (0.2-0.3 м/с)
- Люди видят робот и обходят
- Робот часто поворачивается (периодически "видит" заднюю зону)
- Emergency stop может быть реализован через другие системы

### 5. Митигация

**Сейчас (бесплатно):**
- ✅ Forward-only navigation
- ✅ Повороты перед движением
- ✅ Медленная скорость
- ✅ Сигнальные звуки (у вас есть sound_player!)

**Опционально (если проблема):**
- Добавить 1-2 ультразвуковых датчика сзади (~$5-10)
- Proximity sensors сзади для emergency stop
- Звуковой/световой сигнал при движении назад

**Вывод:** Для большинства задач слепая зона сзади не проблема благодаря стратегии forward navigation.

## Вопрос: NVIDIA Jetson Orin Nano - как использовать CUDA?

**Короткий ответ:** Прямо сейчас - просто быстрее работает на CPU. В будущем - GPU для AI.

### Этапы использования Jetson

#### Фаза 1-4 (текущий план): CPU-only
**Что используется:**
- 6-ядерный CPU Cortex-A78AE
- Многопоточная обработка SLAM
- Параллельная обработка sensor fusion
- Высокие частоты обновления (10Hz costmaps)

**GPU пока не нужен**, но:
- ✅ Огромный запас производительности
- ✅ Нет узких мест
- ✅ Можно повысить разрешение карт
- ✅ Можно добавить больше датчиков

#### Фаза 5+ (будущее): GPU Acceleration

**1. CUDA-accelerated SLAM (опционально)**
```bash
# Альтернативные SLAM пакеты с GPU
- KISS-ICP (GPU-accelerated ICP)
- Fast-GICP (CUDA implementation)
- Ускорение 10-20x на scan matching
```

**2. Семантическое картографирование (рекомендуется)**
```python
# YOLOv8 на GPU для детекции объектов
import tensorrt  # Оптимизация для Jetson
model = YOLO('yolov8n.engine')  # TensorRT engine

# Real-time inference: 30-60 FPS
results = model(camera_frame)
# Определяет: person, chair, door, wall, etc.
```

**3. Visual odometry (дополнительно)**
- Камера как дополнительный источник одометрии
- GPU-accelerated feature matching
- Компенсация drift от wheel encoders

### Практический roadmap

**Неделя 1-4: Установка Jetson**
```bash
# Базовая настройка
sudo apt install nvidia-jetpack  # CUDA, cuDNN, TensorRT
sudo apt install ros-humble-desktop
sudo nvpmodel -m 0  # Max performance

# Мониторинг
jtop  # Смотрим загрузку CPU/GPU
```

**Неделя 5-8: Базовая навигация**
- Запуск лидара
- SLAM на CPU (6 ядер достаточно!)
- Nav2 navigation
- GPU простаивает (0% загрузка) - это нормально

**Месяц 3+: GPU задачи**
- Добавить камеру
- YOLOv8 inference на GPU
- Semantic mapping
- GPU загрузка 30-50%

### Конкретные оптимизации для текущего проекта

**slam_toolbox_params.yaml:**
```yaml
num_threads: 6  # Используем все ядра CPU
ceres_linear_solver: SPARSE_NORMAL_CHOLESKY  # Параллельный
```

**nav2_params.yaml:**
```yaml
local_costmap:
  update_frequency: 10.0  # Вместо 5.0 (Jetson справится)
  resolution: 0.03        # Вместо 0.05 (выше детализация)
```

**Результат:**
- Карты обновляются в 2x быстрее
- Разрешение на 40% выше
- Более точная навигация
- CPU загрузка ~40% (есть запас!)

## Вопрос: ROS2 Iron vs Humble - что выбрать?

**Рекомендация: Оставаться на Humble** ✅

### Сравнение

| Параметр | Humble | Iron | Рекомендация |
|----------|--------|------|--------------|
| **LTS Support** | До 2027 | EOL май 2024 ❌ | Humble |
| **Стабильность** | Отличная | Хорошая | Humble |
| **Waypoint save/load** | Нет | Есть | Humble + Python скрипт |
| **Пакеты ecosystem** | Полный | Полный | Равны |
| **Robotics UI** | Нет | Есть | Humble (можно без UI) |

### Что теряете на Humble?
1. **Встроенное save/load waypoints в RViz**
   - Решение: Python скрипт (50-100 строк, 1-2 дня)
   - Даже лучше: больше гибкости, интеграция с вашим AI

2. **Robotics UI (web interface)**
   - Решение: RViz достаточно для разработки
   - Foxglove Studio как альтернатива

### Что выигрываете на Humble?
1. ✅ **LTS до 2027** - обновления безопасности, bugfixes
2. ✅ **Стабильность** - проверено временем
3. ✅ **Совместимость** - все ваши текущие пакеты работают
4. ✅ **Документация** - больше tutorials и примеров

### Если апгрейд, то когда?
**Вариант 1:** ROS2 Jazzy (LTS до 2029)
- Выйдет в мае 2024
- Следующая LTS версия
- Ждать стабилизации экосистемы ~6 месяцев

**Вариант 2:** Остаться на Humble до 2026-2027
- Достаточно для всех текущих задач
- Миграция когда будет реальная необходимость

**Вывод:** Iron уже устарел (EOL), переход не имеет смысла. Humble идеален.

## Вопрос: Нужно ли добавлять задние датчики?

**Короткий ответ:** Не обязательно сейчас. Можно добавить позже если возникнет проблема.

### Decision tree

```
Вопрос: Робот застревает или сталкивается с препятствиями сзади?
  ├─ НЕТ → Датчики сзади НЕ нужны ✅
  │
  └─ ДА → Анализ причины:
      ├─ Робот движется назад часто
      │   └─ Решение: Настроить allow_reversing=false
      │
      ├─ Люди сталкиваются с роботом
      │   └─ Решение:
      │       1. Звуковой сигнал при остановке
      │       2. Световая индикация сзади
      │       3. Опционально: 1-2 задних датчика
      │
      └─ Робот застревает в тупиках
          └─ Решение: Улучшить exploration параметры
```

### Практические рекомендации

**Фаза 1-3 (Симуляция):**
- ❌ Задние датчики НЕ нужны
- Тестируйте навигацию
- Смотрите как робот справляется

**Фаза 4 (Реальный робот):**
- ⏳ Протестируйте в реальных условиях
- Запишите проблемные ситуации
- Решите: нужны ли датчики

**Если нужно добавить:**
```
Вариант A: 1 задний ультразвуковой (центр)
- Стоимость: ~$5
- Время установки: 1 час
- Покрытие: ~30° сзади
- Достаточно для emergency stop

Вариант B: 2 задних ультразвуковых (левый+правый)
- Стоимость: ~$10
- Время установки: 2 часа
- Покрытие: ~120° сзади
- Полное заднее покрытие
```

**Вывод:** Начните без задних датчиков. 99% роботов с дифференциальным приводом работают только с передними сенсорами благодаря forward-only navigation.
