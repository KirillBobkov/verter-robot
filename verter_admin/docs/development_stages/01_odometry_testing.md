## 📖 Обзор

### Что такое одометрия?

**Одометрия** (от греч. "hodos" - путь, "metron" - мера) - процесс определения положения робота в пространстве на основе данных о его движении.

**Аналогия из жизни:**
Представь, что ты стоишь с закрытыми глазами. Если ты пройдешь 5 шагов вперед и повернешься налево на 90°, ты можешь вычислить своё новое положение относительно начальной точки. Именно это делает одометрия для робота.

### Зачем это нужно?

1. **Навигация:** Nav2 нужно знать ГДЕ робот находится, чтобы построить путь к цели
2. **Картографирование:** Чтобы строить карту, нужно знать откуда робот смотрит
3. **Планирование пути:** Чтобы объезжать препятствия, нужно знать позицию робота

### Реализованная функциональность

✅ Подписка на команды скорости (`/cmd_vel`)
✅ Публикация одометрии (`/odom`)
✅ Публикация TF трансформации (`odom -> base_link`)
✅ Интегрирование скорости в позицию (50 Гц)
✅ Конвертация Twist команд в CHASSIS команды
✅ Ограничение максимальных скоростей

### ШАГ 6: Проверка данных одометрии

**Цель:** Посмотреть какие данные публикуются в `/odom`

**Команда:**
```bash
ros2 topic echo /odom --once
```

**Результат:**
```yaml
header:
  stamp: {sec: 1760782559, nanosec: 150355664}
  frame_id: odom
child_frame_id: base_link
pose:
  pose:
    position: {x: 0.0, y: 0.0, z: 0.0}
    orientation: {x: 0.0, y: 0.0, z: 0.0, w: 1.0}
  covariance: [0.1, 0.0, 0.0, ...] # 6x6 матрица
twist:
  twist:
    linear: {x: 0.0, y: 0.0, z: 0.0}
    angular: {x: 0.0, y: 0.0, z: 0.0}
  covariance: [0.05, 0.0, 0.0, ...] # 6x6 матрица
```

**Разбор полей:**

#### 📍 Header (метаданные)
- `stamp` - временная метка (Unix time в секундах + наносекунды)
- `frame_id: odom` - система координат "откуда" (начальная точка робота)
- `child_frame_id: base_link` - система координат "куда" (центр робота)

#### 📍 Pose (позиция и ориентация)
**position:**
- `x: 0.0` - робот на старте, не двигался (метры)
- `y: 0.0` - не сместился вбок (метры)
- `z: 0.0` - на плоскости (2D робот)

**orientation:**
- Кватернион `{x:0, y:0, z:0, w:1}` = угол 0° (робот смотрит вперед)
- [Калькулятор кватернионов](https://quaternions.online/)

**covariance (6x6 матрица неопределенности):**
- Значение `0.1` на диагонали = ±10 см погрешность по x, y
- Чем меньше значение - тем точнее одометрия
- Формат: `[x, y, z, roll, pitch, yaw]`

#### 🚗 Twist (скорости)
**linear:**
- `x: 0.0` - скорость вперед/назад (м/с)
- `y: 0.0` - скорость влево/вправо (для holonomic роботов)
- `z: 0.0` - скорость вверх/вниз

**angular:**
- `x: 0.0` - вращение вокруг X (крен)
- `y: 0.0` - вращение вокруг Y (тангаж)
- `z: 0.0` - вращение вокруг Z (рысканье / поворот)

## 🔄 Тестирование TF

### ШАГ 7: Проверка TF топика

**Цель:** Убедиться, что TF трансформации публикуются

**Команда:**
```bash
ros2 topic echo /tf --once
```

**Результат:**
```yaml
transforms:
- header:
    stamp: {sec: 1760782636, nanosec: 450139100}
    frame_id: odom
  child_frame_id: base_link
  transform:
    translation: {x: 0.0, y: 0.0, z: 0.0}
    rotation: {x: 0.0, y: 0.0, z: 0.0, w: 1.0}
```

**Что это:**
- **TF (Transform)** - дерево координатных систем в ROS2
- Описывает где `base_link` (робот) относительно `odom` (стартовая точка)
- Аналогия: GPS координаты, только для робота

**🚨 Почему критично для Nav2:**

Nav2 использует TF для:
1. ✅ Понимания где робот на карте
2. ✅ Планирования пути
3. ✅ Избегания препятствий
4. ✅ Достижения цели

**БЕЗ TF ТРАНСФОРМАЦИИ NAV2 НЕ РАБОТАЕТ!**

## 🧮 Как это работает

### Формула одометрии

```python
# 1. Вычисление временного интервала
dt = время_сейчас - время_последнего_обновления

# 2. Вычисление изменения угла
delta_theta = angular_velocity * dt

# 3. Вычисление изменения позиции
if abs(angular_velocity) < 0.000001:  # Прямолинейное движение
    delta_x = linear_velocity * dt * cos(theta)
    delta_y = linear_velocity * dt * sin(theta)
else:  # Движение по дуге
    radius = linear_velocity / angular_velocity
    delta_x = radius * (sin(theta + delta_theta) - sin(theta))
    delta_y = -radius * (cos(theta + delta_theta) - cos(theta))

# 4. Обновление позиции
x += delta_x
y += delta_y
theta += delta_theta

# 5. Нормализация угла в [-π, π]
theta = atan2(sin(theta), cos(theta))
```

## 🎓 Ключевые концепции ROS2

### Топики (Topics)
Каналы связи между нодами (pub/sub паттерн).

**Пример:**
```
Publisher (odometry_node)
    ↓ /odom
Subscriber (Nav2)
```

### Сообщения (Messages)
Структуры данных, передаваемые в топиках.

**Типы:**
- `nav_msgs/Odometry` - одометрия
- `geometry_msgs/Twist` - команды скорости
- `geometry_msgs/TransformStamped` - TF трансформация

### TF (Transform)
Дерево координатных систем робота.

**Зачем:**
- Nav2 знает где робот
- Сенсоры знают где они расположены
- Визуализация в RViz работает

### Частота обновления
50 Гц = 50 обновлений в секунду = каждые 20 мс

**Почему 50 Гц:**
- Стандарт для одометрии в ROS2
- Достаточно для Nav2
- Не перегружает систему

## 🔍 Проблемы и решения

### Проблема 1: `setup.bash` не находит файлы

**Симптом:**
```
not found: "/путь/к/local_setup.bash"
```

**Решение:**
Запускать ноду напрямую через Python:
```bash
export PYTHONPATH="${PYTHONPATH}:$(pwd)/src"
python3 src/verter_admin/odometry/odometry_node.py
```

---

### Проблема 2: TF не публикуется

**Симптом:**
```
Invalid frame ID "odom" passed to canTransform
```

**Решение:**
- Проверить что нода запущена
- Проверить что `TF broadcaster` инициализирован
- Подождать несколько секунд после запуска

---

### Проблема 3: Одометрия дрейфует

**Симптом:**
Робот стоит, но позиция меняется

**Причина:**
Интегрирование ошибок скорости

**Решение (будущее):**
- Интеграция с IMU (инерциальный датчик)
- Sensor fusion (Kalman filter)
- SLAM для коррекции дрейфа
