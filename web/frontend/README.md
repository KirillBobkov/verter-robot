# Локальный React-интерфейс

`web/frontend` — React/TypeScript/Vite приложение для локального экрана. Его `dist` напрямую обслуживает ROS-нода `web_server_node` из `verter_web` на 8081; rosbridge работает на 9090. Это отдельный интерфейс от NATS-мониторинга 8088 и окна камеры 8089.

## Сборка

Из этого каталога:

```bash
npm ci
npm run build
```

Нужны Node.js/npm; ROS-установщик их не устанавливает. `npm ci` использует package-lock. Результат — `dist/`; копирование в ROS install и сборка colcon для изменения фронтенда не нужны. Обновить страницу после сборки. Запуск обслуживающей ROS-группы описан в [OPERATIONS.md](../../docs/OPERATIONS.md).

## Разработка

```bash
npm run dev:emu
```

Эмуляция задаётся `VITE_EMULATION=1`; перед проверкой управляющих элементов убедиться, что используется именно подменённый транспорт. `npm run dev` запускает обычный Vite на 3000, прокси `/rosbridge` направлен к `ws://localhost:9090`; это уже может быть связь с настоящим роботом. `npm run build` проверяет TypeScript и собирает production-версию. Скрипт `npm run lint` в package.json ссылается на ESLint, но зависимость и конфигурация ESLint не установлены; считать его готовой проверкой нельзя. Проверка форматирования проекта — `python3 tools/format_code.py --check` после установки инструментов по OPERATIONS.md.

Наличие элемента интерфейса не означает работающего backend. API миссий и маршрутов через NATS пока не реализован. Для текущих метрик и ручного управления используется [NATS-контракт](../../docs/NATS_CONTRACTS_V1.md) и мониторинг 8088. Не проверять движения, stop или цели навигации на живом backend без согласования.
