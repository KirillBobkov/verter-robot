# Диагностика UART JK BMS

Отдельный PlatformIO/Arduino проект ESP32, не штатная прошивка ctrl. Нет ROS, BLE, Wi-Fi или команд приводу. `pio run` только собирает бинарник. Загрузка требует согласования, идентификации платы/порта и сохранения полного flash для восстановления.

Текущий `platformio.ini` задаёт **ESP32 RX=GPIO16, TX=GPIO17**. Это назначение программы, а не подтверждение распиновки разъёма BMS. Для RS485 нужен подходящий трансивер; к GPIO нельзя подключать линии RS485, 5 В или питание батареи. Уровни и назначение контактов проверяются по конкретному устройству.

USB-консоль 115200; UART BMS по умолчанию 115200 8N1. При старте передачи нет, TX переведён во вход. Команды:

- `STATUS` — число полученных байтов.
- `READ` — один фиксированный legacy JK 4E57 Read All (0x06), затем TX снова вход. Записи настроек нет.
- `BAUD <скорость>` — смена UART-скорости без запроса: 1200, 2400, 4800, 9600, 19200, 38400, 57600, 115200, 230400, 460800.
- Вывод `RX <millis> <hex>` — принятые порции, сохранять консоль для анализа.

`python tools/decode.py capture.log` разбирает сохранённый файл без открытия serial, проверяет кадр/сумму и декодирует известные поля legacy-протокола. Совместимость с конкретной BMS не гарантируется. Тишина без запроса не доказывает неисправность, а эхо запроса не является ответом BMS. BLE JK02 и UART 4E57 — разные протоколы.

Сырой полный ответ может содержать пароль: логи не публиковать. `charging_enabled` означает разрешение MOSFET, а не факт зарядки. Для штатной телеметрии используется BLE-сервис Jetson, описанный в [INSTALL.md](../../docs/INSTALL.md).
