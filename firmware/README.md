# Прошивки ESP32

Штатные проекты PlatformIO:

| Каталог | Назначение |
|---|---|
| `esp32_ble_control/` | ESP32 ctrl, управление и связь micro-ROS |
| `esp32_sensors/` | IMU и УЗ-датчики, связь micro-ROS |

Шасси обслуживает `chassis_zlac_node` из `verter_drivers`: Jetson напрямую связан с ZLAC по RS485/Modbus через `/dev/chassis`. Прошивка отдельного ESP32 шасси не используется. BMS штатно читает отдельный Python BLE-сервис Jetson.

Для установленного в проекте PlatformIO из корня репозитория выполнить `source tools/env.sh`, затем `vendor/platformio/penv/bin/platformio run -d firmware/esp32_sensors` (заменить имя проекта при необходимости). Если `pio` отдельно доступен в PATH, в каталоге прошивки можно использовать `pio run`; плату, окружение и зависимости задаёт `platformio.ini`. Установщики всей системы не прошивают платы автоматически. Загрузка — отдельное согласованное действие после идентификации платы и порта, проверки владельцев порта и сохранения полного flash. USB-UART с одинаковыми идентификаторами нельзя различать только по by-id. Не останавливать агент другого ESP32.

Диагностические проекты не входят в автозапуск:

- `esp32_bms_probe` — UART-приём и фиксированный запрос JK legacy 4E57.
- `esp32_bms_rs485_probe` — UART через внешний RS485-трансивер, выбор RX/TX, скорости и фиксированный запрос чтения; автоматическое направление зависит от трансивера.
- `esp32_bms_passive_diag` — только приём UART на выбранной скорости/пине.
- `esp32_imu_probe` — чтение идентификаторов, регистров и измерений IMU.
- `esp32_imu_init_probe` — эксперимент инициализации/калибровки IMU; меняет временные настройки датчиков.

Их README описывают ограничения конкретных тестов. Загрузка диагностической прошивки заменяет штатную функцию ESP32; аппаратные проверки не являются обычными unit-тестами. Для воспроизводимости сохранять версию PlatformIO/toolchain, профиль платы и SHA-256 полученного бинарника.

[Установка системы](../docs/INSTALL.md) · [Регистры ZLAC](../docs/reference/ZLAC8015D_Modbus_Registers_RU.md)

`build_artifacts/manifest.json` описывает конкретные сохранённые бинарники. Совпадение их с текущими исходниками нужно проверять; изменение исходников само по себе не обновляет бинарники или прошивку платы.
