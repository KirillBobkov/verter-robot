# Картографирование и оценка качества

Откройте мониторинг на порту 8088 и окно «Карта и положение робота» (`/map`).
Оператор включает mapping из основного окна. Просмотр, масштабирование,
наложение точек и сохранение карты не отправляют скорости, stop или цели навигации.
Движение выполняет только оператор через согласованный источник управления.

В новой сессии SLAM первый принятый скан задаёт начало координат
`map`. Продольная ось робота в этот момент совпадает с +X карты и смотрит
вправо в вебе. Если нужно выровнять карту по стене, поставьте робот
параллельно этой стене перед запуском картографирования.

## Сохранение

После остановки робота оператором задайте имя, например `floor_1`, и нажмите
«Сохранить карту и граф SLAM». Дождитесь сообщения «Сохранено».
Режим картографирования продолжает работать. Существующее имя не перезаписывается.

Файлы находятся в `/home/jetson/verter-robot/data/maps/`:

- `floor_1.yaml` и `floor_1.pgm` — карта для локализации и навигации;
- `floor_1.posegraph` и `floor_1.data` — граф и данные SLAM для последующего
  восстановления средствами slam_toolbox;
- `floor_1.manifest.json` — размеры и SHA-256 четырёх файлов.

Принятие запроса ещё не означает завершение. При ошибке проверьте статус:
сетка могла сохраниться, даже если сохранение графа не удалось. Повторная попытка
использует новое имя. Файлы не удаляются автоматически. Сетка и граф снимаются
последовательно: это не транзакционный снимок, поэтому сохраняйте стоящий робот.
Сохранение не добавляет карту в allowlist навигации автоматически и не меняет
текущую локализацию. API описан в [MAP_API_V1.md](MAP_API_V1.md).

Из терминала сетку можно сохранить отдельно:

```bash
cd /home/jetson/verter-robot
tools/verter save-map /home/jetson/verter-robot/data/maps/floor_1
```

Эта CLI-команда сохраняет только YAML/PGM. Для полного комплекта используйте
кнопку или NATS `map.command.save`.

## Просмотр и удаление

Откройте вкладку «Карты» в окне карты. Выберите сохранённую карту и нажмите
«Просмотреть». Сетка откроется в том же окне. Кнопка «К текущей карте»
возвращает живую сетку, скан и положение робота.

Чтобы удалить сохранённую карту, нажмите «Удалить…» и
подтвердите действие. Удаляется комплект файлов этой карты. Карты,
которые используются роботом, заданы в конфигурации локализации или
имеют сохранённые точки либо маршруты, защищены от удаления.

## Как читать наложение

«Точки лидара» показывает текущий /scan зелёным поверх накопленной карты.
Преобразование выполняется через TF в map на временной метке скана, включая
смещение и поворот установленного лидара. Точки не привязываются к экранному
центру и не поворачиваются вручную в браузере. Просроченное облако скрывается.
Это плоская проекция последнего скана, а не накопленная 3D-карта.

Двойные стены, которые всё сильнее поворачиваются при повторных проходах,
требуют проверки согласования сканов, времени и угловой одометрии. Постоянная
ошибка крепления обычно даёт постоянное смещение; накопление само по себе
не доказывает неверный фиксированный yaw. Совпадение облака на стоящем роботе
не доказывает точность карты во всех помещениях.

## Проверка входных данных M10P

Драйвер использует фиксированную сетку из 1800 ячеек с шагом 0,2°.
Диапазон beam_count_min/max в диагностике /map должен быть одинаковым;
angle_increment не должен меняться между сообщениями. Пропуски остаются inf,
задний сектор фильтруется без изменения индексов. Метка header относится к
первому элементу массива; time_increment отрицателен из-за обратного порядка
углов относительно вращения энкодера.

Реализация, ограничения точности времени, сборка и изолированные проверки:
[M10P_DRIVER.md](M10P_DRIVER.md). Старый процесс не подхватывает новый код
автоматически. После изменения геометрии нужна новая сессия SLAM, без
продолжения старого графа на другом представлении сканов.

Предупреждения `LaserRangeScan contains … expected …` означают несовместимость
числа лучей с моделью, созданной SLAM. Их не должно появляться в новом сеансе.
Стабильная геометрия — необходимая проверка входа, а не оценка точности карты.

## Проверка после исправления входных данных

Оператору стоит начать с небольшого помещения с различимыми углами: плавно
проехать замкнутый маршрут, вернуться в исходную область и посмотреть,
совпали ли стены и зелёные точки. Для диагностического прохода можно выбрать
малую скорость порядка 0,05–0,1 м/с и поворот 0,05–0,1 рад/с. Это ориентиры
для ручного теста, автоматические команды не выполняются.

Если поворот накапливается и после исправления /scan, следующий шаг —
согласованный тест угловой одометрии: сравнить известный физический угол,
энкодеры, /odometry/filtered и IMU; проверить радиус колёс, колею 356 мм,
знаки осей и временное согласование. До этого не маскировать ошибку подбором
loop-closure порогов. Люди и перемещающиеся предметы не должны становиться
основными ориентирами при построении базовой карты.

## Реализация и параметры SLAM

Режим mapping запускает ноду из `verter_slam`, сохраняя ROS-имя `/slam_toolbox`, темы и сервисы
SLAM Toolbox. NATS API просмотра и сохранения карты не меняется. Исходники основаны на SLAM Toolbox
2.6.10; Karto, решатель Ceres и ROS-интерфейсы предоставляет системный пакет той же версии.

Внешний фильтр принимает скан, когда относительно последнего пропущенного скана достигнут
порог **перемещения или поворота**. Учитывается переход угла через ±π. Проверки времени,
паузы и throttle сохраняются. Порог поворота задан в радианах; getter Karto возвращает градусы,
поэтому в исправлении выполняется преобразование единиц.

Параметры находятся в `ros_ws/src/verter_bringup/config/slam/slam_toolbox_params.yaml`:

| Параметр | Значение |
|---|---|
| `minimum_travel_distance` | 0.01 м |
| `minimum_travel_heading` | 0.035 рад, около 2° |
| `minimum_time_interval` | 0.05 с |
| `correlation_search_space_smear_deviation` | 0.03 м |
| `loop_match_minimum_response_fine` | 0.45 |
| `align_map_to_start` | true |

`check_min_dist_and_heading_precisely` отсутствует: SLAM Toolbox 2.6.10 его не поддерживает.
Одометрия поступает через TF `odom → base_footprint` на время скана; подписка на
`/odometry/filtered` напрямую не используется.

Проверка на одной записи частичного маршрута в изолированном ROS дала 132 принятых скана
и P90 невязки 3.0 см по 4022 фиксированным соответствиям точек стен. Это внутренняя
согласованность записи, не гарантированная абсолютная точность карты. Чистый поворот
проверен отдельно, включая ±π и неподвижные интервалы. Полный замкнутый маршрут и поведение
на новых проходах проверяет оператор после согласования запуска и управления.

Сборка и применение — [OPERATIONS.md](OPERATIONS.md). Не продолжать старый диагностический
граф для проверки новой конфигурации: начинать отдельную сессию и сохранять карту под новым именем.
