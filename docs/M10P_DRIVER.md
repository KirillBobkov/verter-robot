# Драйвер M10P: геометрия и время сканов

Рабочий пакет — `ros_ws/src/third_party/lslidar_driver`.
Настройки — `ros_ws/src/verter_bringup/config/lidar/m10p.yaml`.
Цепочка остаётся `/scan_raw → laser_filter → /scan`; маска заднего сектора,
ориентация lidar_link и NATS API не меняются.

## Формирование оборота

Для M10_P приём, сборка оборота и публикация выполняются последовательно в
потоке приёма. Отдельный pubScanThread и общие count_num/pre_time_/time_
не участвуют в этом пути. Другие модели используют прежний обработчик.

`include/lslidar_driver/m10p_scan.h` содержит декодер пакета и сборщик без ROS.
Проверяются заголовок A5 5A, длина 22..500 байт, чётность полезной части,
концевые FA FB и диапазон угла энкодера. Частичные чтения UART собираются до
полной длины; объявленная длина не может переполнить 500-байтовый буфер.

Пакет содержит сектор 15°. Согласно декодеру изготовителя, FFFF — заполнитель:
слова сначала исключаются, затем углы равномерно назначаются оставшимся словам
по их порядковому номеру. Нулевая или выходящая за диапазон дальность не становится
препятствием, но её угловая позиция сохраняется. Ссылка на
[декодер изготовителя](https://raw.githubusercontent.com/Lslidar/Lslidar_ROS2_driver/LS-S1_V1.0/lslidar_driver/src/lslidar_x10_driver.cpp).

Выходная сетка фиксирована параметром m10p_scan_bins (по умолчанию N=1800,
допустимо 360..10000). Измерения назначаются ячейкам по фактическому углу;
при совпадении выбирается ближайшая дальность. Пропуски остаются +inf,
интерполяции или растягивания массива нет. Начальный неполный оборот отбрасывается.
После большого разрыва приёма, скачка часов или нарушения порядка углов сборка
снова ждёт границу полного оборота. Массив ограничен N ячейками.

Центры угловых ячеек заданы так:

```text
angle_increment = 2π/N
angle_min       = π/N
angle_max       = 2π - π/N
len(ranges)     = N
```

При N=1800 шаг равен 0,2°, центры — 0,1°…359,9°. Дублированной точки 0°/360°
нет. Диапазон углов, шаг и длина не зависят от количества измерений в пакете.
Поворот и знак координат сохранены: theta_ROS = -theta_encoder modulo 2π.
Параметры исключения углов оставляют ту же геометрию, заменяя дальности на +inf.
Фильтр заднего сектора далее заменяет свои отсчёты на NaN.

## Временные метки

В конфигурации используется время Jetson, use_gps_ts=false. Оценка времени
измерений начинается со времени получения полного пакета; из него вычитаются
длительность передачи UART 8N1 (len*10/500000 с) и время оставшихся измерений
сектора. Период оборота измеряется между последовательными границами 360°→0°.
Начальная оценка до первого полного оборота — 1/12 с.

Энкодер растёт по часовой стрелке, массив ROS — против. Поэтому последовательность
элементов массива идёт назад по времени, что отражается знаком time_increment:

```text
scan_time       = T, измеренный период полного оборота
time_increment  = -T/N
header.stamp    = t_границы_конца - T/(2N) + m10p_time_offset
t_луча_i       = header.stamp + i*time_increment
```

header.stamp относится к первому элементу массива, как требует
[LaserScan.msg](https://raw.githubusercontent.com/ros2/common_interfaces/humble/sensor_msgs/msg/LaserScan.msg).
Он не подменяется временем публикации. Отрицательный time_increment нельзя
самовольно заменять положительным: это перевернёт временной порядок лучей.
PointCloud2, если включён, получает согласованные метки отдельных точек.

Это оценка по часам хоста, а не аппаратная синхронизация: задержки обработки
в лидаре, USB и очередях ОС точно не измерены. m10p_time_offset — дополнительное
калиброванное смещение в секундах (по умолчанию 0, предел ±0,1 с). Подбирать его
без согласованного измерения не следует. GPS-время в новом пути M10P пока
не поддерживается; use_gps_ts=true приводит к явной ошибке конфигурации.

## Сборка и проверки

Из корня проекта:

```bash
source tools/env.sh
cd ros_ws
CMAKE_BUILD_PARALLEL_LEVEL=1 colcon build --symlink-install --packages-select lslidar_driver --executor sequential --cmake-args -DBUILD_TESTING=ON
colcon test --packages-select lslidar_driver --event-handlers console_direct+
colcon test-result --verbose
```

C++-тест проверяет заполнители, переменные размеры пакетов, постоянную сетку,
отбрасывание неполного оборота, пропуски, время и сброс после скачка часов.
Его можно отдельно собрать с AddressSanitizer/UndefinedBehaviorSanitizer.

Проверка реального исполняемого файла через синтетический UART и настоящий
фильтр выполняется строго в отдельном ROS-домене:

```bash
ROS_DOMAIN_ID=87 ROS_LOCALHOST_ONLY=1 python3 src/third_party/lslidar_driver/tests/test_m10p_serial.py install/lslidar_driver/lib/lslidar_driver/lslidar_driver_node src/verter_bringup/config/laser_filters/m10p_filter.yaml
```

Тест создаёт собственный /dev/pts, не открывает физический UART. Проверяет
фрагментацию пакетов, сканы квадратной комнаты, время, PointCloud2 и заднюю маску.
Команды движения, stop и команды мотору лидара не отправляются.

## Применение и приёмка

Изменение геометрии сканов требует новой сессии SLAM. Сначала сохранить текущую
сетку и граф, согласовать завершение mapping, затем собрать и перезапустить
только процесс лидара: hardware.launch.py перезапускает его через respawn.
Перезапуск chassis/ESP32, всего hardware или supervisor для этого не требуется.
Работающий процесс сам по себе не подхватывает новый бинарник и параметры.

Штатное завершение режима через supervisor отправляет нулевую /cmd_vel.
При запрете любых команд без согласования этот шаг требует отдельного разрешения
оператора. Обходить это прямым убийством SLAM ради смены режима не следует.

После применения пассивно проверить /scan_raw и /scan:

- ровно 1800 отсчётов, постоянные углы и согласованный angle_max;
- возрастающие header.stamp, положительный scan_time около периода оборота,
  time_increment отрицателен и abs(time_increment)*N≈scan_time;
- отсутствие новых сообщений Karto о несовпадении числа лучей;
- диапазон beam_count_min/max в map diagnostics одинаковый;
- прежнее направление облака и сохранённая маска заднего сектора.

Проверка качества при движении выполняется только оператором отдельно.
Пассивная проверка формата не доказывает точность колеи, одометрии или карты.
