## 1. Главное для текущего робота

| Назначение | Адрес | Формат / смысл |
|---|---|---|

Python-драйвер `verter_drivers/chassis/chassis_zlac_node.py` записывает `1000` в `0x2000`. Это соответствует адресу и единицам руководства. Адрес `0x2007` не является регистром тайм-аута связи.

### Что именно подтверждено про watchdog

На странице 13 параметр `0x2000` называется «время защиты при потере связи» (`通讯掉线保护时间`) между хостом и приводом. Остановка при потере управляющих команд должна проверяться аппаратным тестом конкретной конфигурации.

В PDF не уточнено, какой обмен сбрасывает таймер: любое корректное обращение Modbus, только запись задания скорости или иной набор команд. Не определена и семантика значения 0. Поэтому наличие аппаратной функции подтверждено, а различие «пропали записи скорости, но чтение энкодеров продолжается» / «пропал весь обмен» остаётся отдельным вопросом проверки. Это не утверждение, что функция на роботе не работает.

## 2. Протокол и кодирование

Источник: PDF, страницы 3–5.

- RS485, Modbus RTU, 8 бит данных, без чётности, 1 стоп-бит — **8N1**.
- Скорость по описанию: 115200 bit/s; варианты задаются кодом в `0x2002`.
- Адрес: в вводном тексте указан default 1 и диапазон 0–127, в таблице `0x2001` — default 4 и диапазон 1–127. Для настройки использовать 1–127; текущий адрес Verter в коде — 1. Противоречие default не устранено самим документом.
- Поддерживаются `0x03` — чтение регистров, `0x06` — запись одного, `0x10` — запись нескольких последовательных регистров.
- Адреса в справочнике — непосредственно адреса в PDU: например, `0x2088`, без прибавления 40001.
- Внутри адресов и 16-битных значений старший байт передаётся первым.
- CRC16 Modbus передаётся младшим байтом первым. Подписи high/low у CRC в PDF перепутаны относительно стандартного порядка; сами многие примеры кадров имеют корректный CRC. Основание порядка CRC: [Modbus Serial Line V1.02, §2.5.1.2](https://modbus.org/docs/Modbus_over_serial_line_V1_02.pdf).

| Обозначение | Значение |
|---|---|
| U16 | Беззнаковое 16-битное значение |
| I16 | Знаковое 16-битное значение, дополнительный код |
| RO | Только чтение |
| RW | Чтение и запись |
| RW/S | Метка из оригинала для сохраняемых параметров; точный момент сохранения не разъяснён. Также существует команда EEPROM `0x2010` |

Не следует считать, что все RW/S автоматически записываются в EEPROM на каждом запросе: PDF не даёт достаточно чёткого описания механизма.

Формулы преобразования:

```python
def signed16(raw):
    return raw - 0x10000 if raw & 0x8000 else raw

def signed32_from_words(high, low):
    raw = (high << 16) | low
    return raw - 0x100000000 if raw & 0x80000000 else raw

target_word = target_rpm & 0xFFFF
actual_rpm = signed16(feedback_word) / 10.0
position_counts = signed32_from_words(position_high, position_low)
```

Пример: задание `100` означает 100 RPM, обратная связь `100` означает 10 RPM. `0xFF9C` как I16 равно −100: это −100 RPM для задания и −10 RPM для обратной связи.

Двигатели обозначены «левый/правый» по руководству. Соответствие каналов физическим колёсам и знак движения определяются монтажом. В текущем Python-коде Verter знаки заданий каналов различаются; это не свойство протокола Modbus.

Значения являются степенями двойки, но PDF явно не объясняет одновременное объединение нескольких ошибок. Сохранять сырое слово; интерпретацию нескольких установленных битов считать неподтверждённой до проверки. Заголовок `0x603F` в таблице на странице 12 не заменяет явно указанные адреса RS485 `0x20A5/0x20A6`.

### Исключения протокола

| Ответная функция | Исходная операция |
|---|---|
| `0x83` | Ошибка чтения `0x03` |
| `0x86` | Ошибка записи `0x06` |
| `0x90` | Ошибка записи `0x10` |

Коды исключений: `0x01` — неверная функция; `0x02` — неверный адрес данных; `0x03` — неверное значение. Это ошибки протокола, отдельные от ошибок двигателей.

## 7. Ошибки и неоднозначности источников

| Место | Наблюдение | Решение в справочнике |
|---|---|---|
| Заметки / альтернативная прошивка | `REG_COMM_WATCHDOG_MS = 0x2007` | По PDF watchdog `0x2000`, `0x2007` — блокировка вала |
| Заметки | `REG_FW_VERSION = 0x0001` | По PDF версия ПО `0x20A0`; назначение `0x0001` этим PDF не подтверждено |
| Заметки | `0x20AB/AC` подписаны RPM без масштаба | Обратная связь имеет масштаб 0,1 RPM |
| Заметки | `REG_DRIVER_STATUS = 0x20A5` | Это ошибка левого канала. Чтение блока с этого адреса допустимо; имя может вводить в заблуждение |
| PDF, страницы 3 и 13 | Разные default адреса: 1 и 4 | Не выбирать default без проверки фактического адреса |
| PDF, страницы 4–5 | CRC high/low подписаны наоборот | Использовать порядок Modbus CRC low → high |
| PDF, страница 5 | Ответ на запись 2 регистров показан как `01 10 20 30 02 4A 07 01` | Поле количества не совпадает с запросом `00 02`; пример не копировать |
| PDF, страницы 7 и 10 | Некоторые команды stop/enable отправлены в `0x2031` | Противоречит каталогу: `0x2031` — Hall offset. Использовать `0x200E` по таблице и согласованным примерам |
| PDF, страницы 10 и 17 | У `0x2086/87` единицы mA/s, default записан `300ms` | Число 300 и пометку противоречия сохранить; ms не приписывать как достоверную единицу регистра |
| PDF, страницы 16–17 | Default Kf позиции: левый 50, правый 1000 | Перенесено дословно по значениям; не «исправлено» до симметрии |
| PDF, страница 19 | `0x20AF` почти не описан | Не использовать как доказанный heartbeat/watchdog без дополнительного подтверждения |

## 8. Связь с кодом Verter

Файлы действующего драйвера:

- `/home/jetson/verter-robot/ros_ws/src/verter_drivers/verter_drivers/chassis/chassis_zlac_node.py`
- `/home/jetson/verter-robot/ros_ws/src/verter_bringup/config/chassis.yaml`

Python-драйвер пишет режим 3 в `0x200D`, watchdog 1000 ms в `0x2000`, enable в `0x200E`, две скорости с `0x2088`. Он читает 8 регистров начиная с `0x20A5`: две ошибки, четыре слова позиции и две фактические скорости. Одометрия вычисляется из приращений позиции энкодеров. Масштаб регистров фактической скорости RPM не является масштабом приращений позиции.

Справочник не подтверждает текущие значения регистров или действие watchdog на конкретном приводе; для этого нужна отдельная аппаратная проверка.

## 9. Аппаратная проверка настроек

1. Подтвердить версию устройства и текущие значения нужных параметров через единственного владельца Modbus-порта; не подключать второй master параллельно работающему драйверу.
2. Раздельно проверить прекращение всего обмена и прекращение записей скорости при продолжающемся опросе; зафиксировать действие `0x2000`.
3. Проверить масштаб фактической скорости и counts/rev, порядок каналов и знаки колёс.
4. Сопоставить S-времена с измеренными разгонами и тормозным путём при рабочих скоростях.
5. Для неиспользуемых регистров оставить документацию как справочную; не менять настройки двигателя только ради заполнения таблицы.
