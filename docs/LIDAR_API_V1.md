# Лидар: NATS и 2D-просмотр v1

`verter-lidar.service` — отдельный Python-сервис наблюдения. Читает ROS `/scan`
(`sensor_msgs/msg/LaserScan`) и TF, публикует NATS Core и обслуживает окно на 8090.
Поток lidar не содержит команд движения, переключения режимов или записи KV.
Это текущий отфильтрованный 2D-скан, не карта и не накопленное 3D-облако.

## NATS

| Subject | type | Частота |
|---|---|---|
| `<robot_id>.lidar.update.scan` | `scan` | не более 5 Гц, только новые свежие сканы |
| `<robot_id>.lidar.update.model` | `model` | 1 Гц для подключения новых клиентов |
| `<robot_id>.lidar.update.status` | `status` | 1 Гц |

UTF-8 JSON. Это потоковые сообщения специального формата, **не** конверты
`value/unit` обычных метрик. В JetStream/KV они не записываются. Клиенту достаточно
подписки на `<robot_id>.lidar.update.*`; через настроенный leaf сервер использует
тот же контракт. NATS leaf сейчас не настроен. Каталог — [LIDAR_CATALOG_V1.json](LIDAR_CATALOG_V1.json).
Базовый `service.schema_get`/`metrics_get` этот отдельный поток не агрегирует.

Скан:

```json
{
  "v": 1,
  "type": "scan",
  "robot_id": "verter_01",
  "boot_id": "идентификатор запуска",
  "sequence": 15,
  "sample_at": 1791360000.25,
  "max_age_s": 1.5,
  "frame_id": "lidar_link",
  "target_frame": "base_footprint",
  "ros_stamp": {"sec": 1791360000, "nanosec": 230000000},
  "angle_min": 0.0,
  "angle_increment": 0.01,
  "range_min": 0.1,
  "range_max": 30.0,
  "original_points": 3,
  "stride": 1,
  "ranges": [1.25, null, 2.1],
  "transform": {"translation": [0.0, 0.0, 0.86], "rotation_xyzw": [0.0, 0.0, 1.0, 0.0]}
}
```

Значения примера условные. Расстояния и translation — метры, углы — радианы.
`sample_at` — Unix-время получения на Jetson; `ros_stamp` — исходная метка ROS.
Скан с отклонением метки от ROS-часов наблюдателя более 2 секунд отвергается.
NaN/Infinity и расстояния вне range_min/range_max превращаются в `null`.
Расстояния округляются до 0,0001 м, что не означает такую точность измерения.

Массив содержит не более 2048 отсчётов. Для длинного массива используется каждый
`stride=ceil(original_points/2048)`-й отсчёт, начиная с нулевого. `angle_increment`
уже умножен на stride; повторно умножать его нельзя. Угловые пропуски и `null`
не означают свободное пространство. Последний угол вычисляется из длины массива.

Точка в frame лидара: `p=(r*cos(angle_min+i*angle_increment), r*sin(...), 0)`.
Для показа на корпусе применить `p_base = R(rotation_xyzw)*p + translation`.
TF получен для времени скана. При отсутствии преобразования точки не публикуются;
ошибка отображается в status. Для вида сверху берутся координаты X/Y после полного
3D-преобразования. Направление вперёд — +X, влево — +Y.

`sequence` растёт внутри `boot_id`; после перезапуска начинается заново.
Офлайн-очереди нет. Клиент заменяет предыдущий кадр новым и самостоятельно проверяет
возраст; при потере источника кадры не повторяются как новые измерения.

## Модель и состояние

`model`: `{v,type,robot_id,frame_id,unit,source,polygons}`. `frame_id=base_footprint`,
`unit=m`. Каждый polygon содержит `name`, `kind=body|wheel`, `points=[[x,y],...]`.
Модель получается из активного URDF: проекция collision корпуса и четырёх колёс,
с применением fixed-joint transforms. Корпус показан охватывающим прямоугольником,
а не подробным контуром CAD mesh. Это схема в масштабе, не динамическая 3D-модель.
После изменения URDF требуется перезапуск службы просмотра.

`status`: `{v,type,robot_id,updated_at,stale,error,age_s,frame_id,topic,max_age_s}`.
`topic=/scan`, `max_age_s=3`. `stale=true`, если скана ещё нет, его возраст более
1,5 секунды либо возникла ошибка обработки/TF. `error` — строка или null,
`age_s` — возраст последнего успешно обработанного скана или null.
При остановке службы сообщения исчезнут: подписчик обязан проверять возраст status.

## HTTP и WebSocket

- `GET /` — окно просмотра.
- `GET /static/...` — JS/CSS.
- `GET /api/lidar/status` — последнее состояние из NATS с проверкой возраста;
  до первой публикации возвращает `{v:1,stale:true,error:"waiting_nats"}`.
- `GET /api/lidar/ws` — WebSocket, только сервер → клиент; binary frames с UTF-8 JSON.
  Передаёт те же scan/model/status из подписки NATS, дополненные `delivery_age_s`.
  Для scan это возраст по sample_at, не меньший времени хранения в локальном кеше.

Host allowlist и same-origin проверяются; HTTP-токена нет. До четырёх зрителей,
далее HTTP 429. При запрещённом Host/Origin — 403. При отправке прикладных сообщений
в WebSocket сервер закрывает его с кодом 1008. Медленный зритель не накапливает
кадры: хранится только последнее сообщение каждого типа, отправка ограничена
тайм-аутом 2 секунды. При выключенном `web_enabled` NATS-публикация продолжает работать.

Окно скрывает точки после 1,5 секунды без свежего скана; модель остаётся видимой.
Масштаб 1–20 м, сетка в метрах, перед робота обозначен стрелкой.
Сверху размещена общая панель ручного управления кнопками и клавиатурой.

## Подключение

Из доверенной Wi-Fi сети: `http://<IP-Jetson>:8090/`, IP должен быть в
`config/nats/lidar.json:web_allowed_hosts`. Кнопка на мониторинге 8088 открывает
тот же hostname на 8090. При другом локальном порте туннеля открыть адрес вручную.

```bash
ssh -p 3333 -N -L 8090:127.0.0.1:8090 jetson@109.195.134.20
```

Открыть `http://127.0.0.1:8090/`. WebSocket работает через этот TCP-туннель;
WebRTC, UDP и TURN для лидара не нужны.

Исходники — `services/lidar/`; запуск — `tools/start-lidar.sh`; unit-шаблон —
`deploy/verter-lidar.service.in`; приватная конфигурация — `config/nats/lidar.json`.
Установка и обслуживание — [INSTALL.md](INSTALL.md), [OPERATIONS.md](OPERATIONS.md).


Панель управления, HTTP-прокси команд и фокус клавиатуры описаны в
