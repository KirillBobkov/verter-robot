# Costmap Nav2 через NATS и окно карты

Контракт JSON v1, ревизия общего контракта NATS **1.8**. Это API чтения локального и глобального costmap; он не меняет режим, не запускает Nav2, не отправляет скорость, остановку, начальную позу или навигационные цели. Существующие контракты карты и положения робота сохраняются.

Локальный интерфейс `/map` на порту 8088 получает эти же данные через HTTP → NATS request/reply. Серверное приложение может пользоваться NATS напрямую и рисовать те же слои. Открытие страницы и включение видимости слоя — только просмотр.

## Что показывает слой

`local` — объединённый локальный costmap Nav2: лидар, камера, УЗ и инфляция препятствий. `global` — объединённый глобальный costmap: сохранённая карта, текущие препятствия от датчиков и инфляция. Геометрия и обработка датчиков описаны в [COSTMAP.md](COSTMAP.md).

Это итоговые сетки Nav2, а не отдельные облака камеры и УЗ. По клетке итогового costmap нельзя определить, какой датчик её занял. Цвета интерфейса обозначают стоимость клетки, не происхождение измерения. Точки лидара и контур робота остаются отдельными элементами окна карты.

В текущей системе costmap работают в режиме `navigation`. В `idle`, `mapping` и `localization` API сообщает об отсутствии активных costmap; интерфейс не выдаёт сохранённую сетку за свежие препятствия. Просмотр сам не включает навигацию ради получения картинки.

## ROS-источники и координаты

Наблюдатель только читает полные сообщения `nav2_msgs/msg/Costmap`:

| Вид | ROS topic | Исходная система координат |
|---|---|---|
| `local` | `/local_costmap/costmap_raw` | `odom` |
| `global` | `/global_costmap/costmap_raw` | `map` |

В Humble эти raw-топики публикуют полную сетку, даже если `always_send_full_costmap: false`; подписываться на `costmap_updates` или собирать патчи для этого API не требуется. Временная метка берётся из `header.stamp` raw-сообщения. [Исходник Nav2 Humble](https://github.com/ros-navigation/navigation2/blob/humble/nav2_costmap_2d/src/costmap_2d_publisher.cpp).

Ответы нормализованы в систему **`map`**. `source_frame_id` сохраняет имя исходной системы, `frame_id` равно `map`. Для локальной сетки backend использует TF `map ← odom` на временную метку сетки и преобразует её origin. Поле `origin={x,y,yaw}` уже находится в `map`: повторно применять к нему TF, позу робота или origin сохранённой карты нельзя. Без подходящего TF сетка недоступна для наложения.

Размеры `width`, `height` задаются в клетках, `resolution` — в метрах на клетку; `origin.x/y` — метры, `origin.yaw` — радианы. Массив хранится построчно: X меняется быстрее Y, индекс `j*width+i`, нижняя строка имеет `j=0`. Центр клетки:

```text
p_map = origin.xy + R(origin.yaw) * resolution * [i + 0.5, j + 0.5]
```

Для экранного изображения строки переворачиваются по Y. Поворот origin необходимо учитывать целиком: растягивание повёрнутой сетки по её прямоугольной bounding box даёт неверное положение препятствий. Изменение локального origin при движении — штатное поведение rolling window; менять по нему масштаб или центр вида не требуется.

## Значения клеток

Сетка содержит исходные **uint8 0…255**, а не значения OccupancyGrid −1…100.

| Значение | Значение для Nav2 | Отображение в вебе |
|---|---|---|
| `0` | Свободно | Прозрачно, сохранённая карта видна снизу |
| `1…252` | Градиент стоимости, включая инфляцию | Полупрозрачная цветовая шкала стоимости |
| `253` | Inscribed inflated obstacle | Выделенная зона высокой стоимости |
| `254` | Lethal obstacle | Занятая клетка |
| `255` | Неизвестно | Прозрачно; не обозначает свободное пространство |

Наложение показывает представление Nav2, но не доказывает физическую безопасность проезда. Инфляция не является гарантированным зазором от корпуса; costmap не предсказывает траектории людей. Ручное управление веба и ESP32 ctrl по-прежнему не проходит через costmap.

## NATS request/reply

Subject: **`<robot_id>.costmap.command.get`**. Action для общего HTTP-конверта: **`costmap.get`**. В прямом NATS-запросе поле action не передаётся.

Пример запроса состояния для `verter_01`:

```json
{
  "v": 1,
  "id": "28360bb0-1e1a-4c7b-b199-a3e5c21f35a3",
  "issued_at": 1793883600,
  "ttl_s": 10,
  "args": {"part": "state"}
}
```

UUID и `issued_at` в примере необходимо заменить: время — текущие Unix seconds, TTL не больше 30 секунд. Ответ — обычный конверт `{v,id,ok,at,result}`; при ошибке `{v,id,ok:false,at,error}`. Чтение не пишется в журнал управляющих команд, не ставится в очередь для последующего исполнения и не зависит от разрешения движения или смены режима.

### Состояние обоих costmap

Args: `{}` либо `{"part":"state"}`.

`result` содержит `v`, `robot_id`, `mode`, `map_id`, `updated_at`, а также `local` и `global` — метаданные каждого costmap. `mode` — строка текущего режима supervisor, например `navigation`, а не полный объект состояния режима. `updated_at` — Unix seconds формирования состояния. Отсутствие одного costmap не подменяется данными другого.

### Метаданные одного costmap

Args: `{"part":"metadata","kind":"local"}` либо `kind:"global"`.

Общие поля: `v`, `robot_id`, `kind`, `available`, `stale`, `reason`, `costmap_id`, `map_id`, `saved_map`, `frame_id`, `mode`, `updated_at`, `age_s`, `max_age_s`. Здесь `mode` также строка фактического режима. `saved_map` — имя выбранной сохранённой карты, если известно; оно не заменяет идентификатор сессии `map_id`. Пока достоверной сетки нет, `age_s` может быть null, геометрия и метка измерения отсутствуют; координаты и размеры не выдумываются.

При доступной сетке дополнительно присутствуют:

| Поле | Смысл |
|---|---|
| `source_frame_id`, `stamp`, `revision` | Исходная система координат, временная метка сетки и номер снимка |
| `width`, `height`, `resolution`, `origin` | Геометрия сетки; origin уже преобразован в `map` |
| `encoding` | `zlib-uint8-row-major` |
| `decoded_bytes` | `width*height` |
| `compressed_bytes` | Размер полного zlib-потока |
| `chunk_bytes` | Размер части сжатых байтов: 49152 |
| `chunks` | Число частей, последняя может быть короче |
| `sha256` | SHA-256 полного сжатого потока |
| `decoded_sha256` | SHA-256 исходных uint8-клеток |

`costmap_id` — непрозрачный идентификатор текущей сессии и вида costmap; клиент не разбирает его внутренний формат. `map_id` должен совпадать с идентификатором отображаемой живой карты из `map.get`. Это идентификатор сессии, а не имя YAML-файла. `revision` выбирает конкретный снимок сетки вместе с его геометрией. При смене сессии нельзя продолжать накладывать старую сетку.

`stamp` — ROS-время исходной сетки в секундах, `age_s` — её возраст. Допустимый возраст `max_age_s`: **1,5 с для local**, **3 с для global**. При `available:false` или `stale:true` слой не рисуется. Пример причины отсутствия: `nav2_not_active`. Причина выводится пользователю; отсутствие сетки не означает, что вокруг свободно.

### Части выбранного снимка

Args:

```json
{
  "part": "chunk",
  "kind": "local",
  "costmap_id": "opaque-current-costmap-id",
  "revision": 4,
  "index": 0
}
```

Ответ содержит `kind`, `map_id`, `costmap_id`, `revision`, `index`, `chunks`, `data_b64`. Последнее поле — base64-кодированная часть сжатого потока. Нумерация `index` начинается с нуля. Все части должны принадлежать одному `kind/map_id/costmap_id/revision`.

Порядок чтения для клиента:

1. Получить свежие metadata и убедиться в совпадении `map_id` с отображаемой картой.
2. Прочитать все части выбранной версии. Отдельно декодировать каждую `data_b64`, затем соединить полученные байты по `index`.
3. Проверить размер `compressed_bytes` и `sha256`, распаковать zlib.
4. Проверить `decoded_bytes`, `width*height` и `decoded_sha256`.
5. Повторно проверить актуальность сессии и свежесть; только затем целиком заменить изображение слоя.

Не следует соединять base64-строки частей как один непрерывный base64-текст, смешивать версии, частично рисовать недокачанную сетку или считать пропущенные клетки свободными. Если версия уже вытеснена, заново запросить metadata и части. Ошибка не запускает никаких действий на роботе.

Максимум — **4194304 клетки (4 МиБ без сжатия)** на одну сетку. В памяти сохраняются **три последние ревизии** каждого вида. Чтение части `index:0` дополнительно закрепляет выбранный снимок на **10 секунд**; одновременно допускаются **два закреплённых снимка суммарно для local и global**. Суммарный бюджет сжатых снимков — **32 МиБ**. При достижении лимитов старые записи могут вытесняться раньше; истёкшие закрепления удаляются при обслуживании кеша.

Закрепление позволяет закончить передачу байтов и не продлевает срок свежести для отображения. Даже успешно скачанную сетку нельзя рисовать после её `max_age_s` или смены сессии. При ошибке `costmap_revision_unavailable_refetch_metadata`, `costmap_revision_stale_refetch_metadata` либо `costmap_not_current_refetch_metadata` клиент перечитывает metadata; отсутствие актуальной версии показывает как недоступный слой. Большие сетки не передаются одним сообщением NATS, очереди всех кадров нет.

## Обновления и KV

| Subject | KV key | Данные |
|---|---|---|
| `<robot_id>.costmap.update.local` | `costmap.local` | Текущие метаданные local |
| `<robot_id>.costmap.update.global` | `costmap.global` | Текущие метаданные global |

Тело события и значение KV — **метаданные напрямую**, без обёртки `value/unit` или observation envelope, как в потоке живой карты. Обновления публикуются не чаще 2 Гц, значения KV обновляются не чаще 1 Гц. Клиент проверяет `available`, `stale`, идентификаторы и возраст даже для прочитанного KV: последнее сохранённое значение само по себе не доказывает свежесть.

Клеток, base64-частей и истории costmap в этих событиях и KV нет. Уведомление позволяет понять, что появилась другая версия; её содержимое читается через request/reply. Перезапуск bridge, завершение navigation или смена владельца режима делает предыдущую сессию недействительной. Устаревшие сетки на экране скрываются.

ACL клиента разрешает запрос `costmap.command.get` только собственного `robot_id`; добавление этого API не даёт права командовать другим роботом. Существующие правила подписки на обновления собственного робота охватывают costmap. Секреты NATS в данный документ и комплект API не включаются.

## HTTP и локальный веб

HTTP выполняет те же NATS-запросы и не читает ROS напрямую:

```text
GET /api/costmap
GET /api/costmap?part=state
GET /api/costmap?part=metadata&kind=local
GET /api/costmap?part=metadata&kind=global
GET /api/costmap?part=chunk&kind=local&costmap_id=...&revision=4&index=0
```

`costmap_id` при построении URL необходимо URL-кодировать. Также доступен общий `POST /api/command` со стандартным конвертом и `action:"costmap.get"`; это тот же запрос чтения. Окно карты для costmap использует только GET. Отключение видимости слоя не меняет настройки Nav2 и не отключает датчики.

При недоступности Nav2, TF, текущей карты или свежих данных интерфейс показывает причину и скрывает соответствующий слой. Он не включает navigation, не восстанавливает локализацию и не отправляет остановку ради просмотра. Отдельная панель ручного управления сохраняет свой прежний явно вызываемый API; запросы costmap к ней не относятся.
