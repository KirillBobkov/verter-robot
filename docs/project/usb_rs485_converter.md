# Изолированный USB↔RS-485 конвертер — спецификация

Документ для инженера, выполняющего сборку шасси на ZLAC8015D. Описывает: что это за компонент, зачем нужна именно изолированная версия, по каким признакам выбирать, какие конкретные модели брать, как подключить и как валидировать.

---

## 1. Роль в системе

ZLAC8015D — промышленный сервоконтроллер, который общается с управляющим компьютером **только по RS-485** в протоколе **Modbus RTU**. У Jetson нет порта RS-485 «из коробки» — есть только USB и UART (TTL). Поэтому нужен **мост USB → RS-485**.

```
┌──────────┐  USB-A    ┌─────────────────────┐  A/B  ┌────────────┐  3 фазы  ┌────────┐
│  Jetson  │──────────▶│ Изолированный       │──────▶│ ZLAC8015D  │─────────▶│ Motor  │
│          │           │ USB-RS-485 конвертер│       │            │          │ + enc  │
└──────────┘           └─────────────────────┘       └────────────┘          └────────┘
                       (FT232 + изолятор + RS-485 трансивер в одном корпусе)
```

Конвертер выполняет три задачи:
1. **Прозрачный последовательный канал** через USB (Linux видит устройство как `/dev/ttyUSB*`).
2. **Преобразование TTL UART → дифференциальный RS-485** (трансивер MAX485/ADM3485/SP3485).
3. **Гальваническая изоляция** между Jetson и силовой шиной шасси.

---

## 2. Зачем нужна именно изолированная версия

Без изоляции земля Jetson через USB соединяется напрямую с землёй RS-485 драйвера, а та — с силовой землёй мотор-каналов. Это создаёт три класса проблем, которые на bench-тесте обычно не проявляются, а на реальном роботе под нагрузкой — гарантированно:

### 2.1 Ground loop noise (помехи по общей земле)
- ZLAC8015D коммутирует мотор-фазы на 24/48В на частотах 16–20 кГц с пиковыми токами в десятки ампер.
- Любой реальный провод имеет сопротивление и индуктивность → на земле «прыгает» напряжение в десятки–сотни милливольт.
- Без изоляции эти прыжки попадают на USB GND Jetson → видны USB-контроллеру как нарушения уровней → CRC-ошибки на USB и/или внезапные disconnect/reconnect.

### 2.2 Surge при старте/реверсе мотора
- В момент включения мотор-каналов и при торможении возникают броски обратной ЭДС.
- На неизолированном конвертере эти броски могут пробить USB-мост (FT232/CP210x) — типичный отказ: устройство «мёртво» до перезагрузки Jetson, иногда — до замены платы.

### 2.3 ESD через провода RS-485
- Витая пара RS-485 идёт по корпусу робота, ловит статику от пола/одежды.
- Без изоляции разряд приходит на USB-шину Jetson.

### Что даёт изоляция
- Цифровой изолятор (ADuM1201 / ADM2483 / Si8621) разрывает прямую гальваническую связь между USB и RS-485 секциями.
- Изолированный DC-DC (B0505S или аналог) питает RS-485-сторону отдельным «плавающим» 5В.
- Стандарт изоляции: **1500–3000 В RMS** между двумя секциями. Эти цифры — не «выдержит молнию», а гарантированный запас для сценариев выше.

**Симптом, который изоляция убивает наповал**: периодические `ModbusIOException: CRC error` или `Unable to read response` при движении робота, исчезающие, когда робот стоит. Это ровно ground-loop noise.

## 3. Критерии выбора (что искать в характеристиках)

| Параметр | Требование | Почему |
|---|---|---|
| **USB-мост** | FT232RL / FT232HL или CP2102 / CP2104 | Стабильные ядерные драйверы (`ftdi_sio` / `cp210x`) в Linux. Hot-plug отрабатывает корректно. **Не CH340/CH341** — на Jetson были случаи зависания и потери символов |
| **Изоляция** | Явно указано «isolated», 1500–3000 В | Без указания напряжения — изоляции, скорее всего, нет |
| **Тип изолятора** | ADuM12xx / ADM2483 / Si86xx (digital) или быстрые оптопары | Старые медленные оптопары ограничивают скорость до 9600–19200; для Modbus 115200 нужен быстрый цифровой изолятор |
| **DC-DC isolation** | Должен быть отдельный изолированный преобразователь питания (B0505S и подобные) | Иначе изоляция «однобокая» — данные изолированы, питание нет |
| **RS-485 трансивер** | MAX485 / MAX3485 / ADM3485 / SP3485 / ISL3175 | Все эквивалентны для нашей скорости (115200) |
| **ESD-защита** | TVS-диоды на A/B | Дополнительная защита от статики |
| **Auto-direction (DE/RE)** | Желательно | Драйвер не должен сам управлять направлением — конвертер делает это автоматически по передаче |
| **Терминирование 120 Ω** | Опционально встроенное (часто перемычкой) | Удобно — один резистор уже на месте |
| **Bias resistors (failsafe bias)** | Опционально встроенные | Улучшают помехоустойчивость на простаивающей шине |
| **Корпус** | Пластиковый или металлический закрытый | Не голая плата — на роботе пыль/влага/механические повреждения |
| **Connector RS-485** | Винтовой клеммник 3-pin (A, B, GND) или DB9 | Винтовой удобнее под витую пару |

## 4. Конкретные модели (3 тира)

### Тир 1 — рекомендуемый по умолчанию: Waveshare «USB TO RS485 (B)»

Это «золотой стандарт» среди недорогих изолированных адаптеров.

- **Чипсет:** FT232RL (USB) + ADM2483 (изолятор + трансивер в одном) + B0505S (изолированный DC-DC).
- **Изоляция:** 2500 В RMS.
- **ESD-защита:** есть, на A/B.
- **Защита от перенапряжения:** TVS на линиях.
- **Скорость:** до 921600 бод (нам хватит 115200 с большим запасом).
- **Connector RS-485:** винтовой клеммник + DB9 (можно использовать любой).
- **Встроенное терминирование:** 120 Ω перемычкой.
- **Корпус:** пластиковый.
- **Цена:** ≈ $18–25 (Aliexpress / официальный магазин Waveshare).
- **Артикул:** «USB TO RS485 (B)» (с буквой B — это именно изолированная версия; есть также не-B вариант без изоляции, его НЕ брать).

**Плюсы:** чипы FTDI ровно работают на Jetson из коробки, изоляция нормальная, цена низкая, документация полная.
**Минусы:** пластиковый корпус (не для уличного робота), нет крепления на DIN-рейку.

### Тир 2 — DTECH / DSD TECH «Industrial Isolated»

- **DTECH USB to RS485 Adapter Cable Industrial Isolated** (модель DT-9026).
- **DSD TECH SH-U10** в **isolated**-исполнении (важно — у DSD есть и неизолированные SH-U10, проверить описание).
- **Чипсет:** FT232RL + изолятор + B0505S.
- **Изоляция:** 1500–2500 В (зависит от ревизии).
- **Форм-фактор:** часто кабель «USB вилка → корпус с винтовым клеммником» — удобно для встраивания.
- **Цена:** ≈ $25–40.

**Плюсы:** компактно, никаких проводов USB↔корпус — сразу кабель.
**Минусы:** качество ревизии «плавает», обязательно сверять чипы по фото платы перед заказом.

### Тир 3 — промышленный для боевой эксплуатации

Если робот идёт в production и стоимость простоя выше стоимости железа.

- **Brainboxes US-320** — USB to RS-485 1 Port Isolated. FT232 + полная изоляция + металлический корпус. ~$100–130.
- **Moxa UPort 1130I** — изолированный, индустриальный, ~$150–200. Есть Linux-драйверы и поддержка от Moxa.
- **ICP DAS I-7561U-DB9** — изолированный, FT232-based, ~$120.

**Плюсы:** сертификация (CE/FCC), металл, ESD ±15 кВ, гарантия от вендора, опт. поддержка.
**Минусы:** цена.

### Что НЕ покупать

- Любые адаптеры на **CH340** / **CH341** — даже если на коробке написано «isolated». Драйвер `ch341` в Jetson Linux менее стабилен под длинными сессиями Modbus, известны случаи потери символов в потоке.
- «USB to RS-485» за $2–3 на синей плате с одной микросхемой и без слова isolated — почти наверняка не изолирован, какие бы фото ни показывал продавец.
- Адаптеры без указания напряжения изоляции в описании — даже если в названии есть «isolated».

## 5. Подключение

### 5.1 Со стороны Jetson (USB)

- **Порт:** любой USB-A на Jetson (предпочтительно USB 2.0; USB 3.0 порты не дают преимущества для serial и иногда более чувствительны к помехам).
- **Кабель USB:** короткий (≤1 м), желательно с **ферритовым кольцом** на конце у Jetson — гасит ВЧ-помехи.
- **Не подключать через USB-хаб** без отдельного питания, особенно дешёвый. Лучше прямо в Jetson.

### 5.2 Со стороны ZLAC8015D (RS-485)

Стандартное подключение полудуплексной шины RS-485 «точка-точка»:

```
Конвертер           Кабель                ZLAC8015D
─────────           ──────                ─────────
A  (D+)  ──── витая пара жила 1 ────────  A
B  (D−)  ──── витая пара жила 2 ────────  B
GND      ──── экран ────────  (один конец) GND-сигнальный
```

**Важные правила:**
1. **A↔A, B↔B**, никаких перекрещиваний. Если на устройстве написано «D+/D−» — это синонимы A/B (D+=A, D−=B).
2. **Витая пара** для A/B обязательна — обычные параллельные провода не работают на длине больше 30 см при 115200 бод. Подходит: одна пара из любого Cat5/Cat6 кабеля, или специализированный Belden 9841 / Alpha Wire 6412.
3. **Экран** заземляется **только с одной стороны** (у Jetson). Иначе по экрану потечёт ground-loop ток.
4. **GND-провод сигнальный** между конвертером и ZLAC — желателен, особенно если длина >2 м. Третий проводник в кабеле, общий «return» для referencing common-mode напряжения.

### 5.3 Терминирование шины

RS-485 — это передающая линия. На концах нужен резистор **120 Ω** между A и B, иначе на скоростях 115200+ возникают отражения сигнала и CRC-ошибки.

Топология робота — два узла, конвертер и ZLAC8015D — это «point-to-point», физически оба узла на концах шины:

```
[USB конвертер]──A───────────────────A──[ZLAC8015D]
                B───────────────────B
                ↑                   ↑
            120 Ω                120 Ω
        (часто встроен)      (надо установить)
```

- **На стороне конвертера:** в Waveshare USB TO RS485 (B) терминатор включается **перемычкой/джампером** на плате. Включить.
- **На стороне ZLAC8015D:** уточнить по мануалу. У большинства драйверов ZLTECH есть DIP-переключатель «120Ω termination» или пин «term» — включить. Если нет — припаять резистор 120 Ω 1/4 Вт прямо на клеммы A/B драйвера.

Если кабель короче 50 см и шина простаивает большую часть времени — иногда работает и без терминаторов. Но это не «надёжно», это «повезло». Ставить.

### 5.4 Bias (подтягивающие резисторы)

Когда оба узла молчат, A/B плавают около 0В дифференциала, и приёмник может «слышать» случайные биты как старт пакета. Bias resistors подтягивают линию в стабильное «idle high» состояние:

- На стороне master (USB-конвертер): 680Ω между A↔+5В и B↔GND.
- В большинстве качественных конвертеров (включая Waveshare B) bias встроен — отдельно ставить не нужно.

## 6. Linux / Jetson — настройка

### 6.1 Проверка распознавания

После подключения:

```bash
dmesg | tail -30
ls -l /dev/ttyUSB*
```

Ожидаемый вывод dmesg для FT232:
```
usb 1-2.3: new full-speed USB device number 5 using tegra-xusb
usb 1-2.3: New USB device found, idVendor=0403, idProduct=6001
ftdi_sio 1-2.3:1.0: FTDI USB Serial Device converter detected
usb 1-2.3: FTDI USB Serial Device converter now attached to ttyUSB0
```

`idVendor=0403` = FTDI. Если вместо этого `1a86` — это CH340 (вернуть в магазин). `10c4` — CP210x (тоже OK).

### 6.2 Драйвер

- **FT232:** ядерный модуль `ftdi_sio` — загружается автоматически, ничего не нужно.
- **CP210x:** `cp210x` — автоматически, но на Jetson известен **тот же баг с пропадающими байтами**, что и для лидара. Если конвертер на CP210x — применить **тот же patch для cp210x**, который уже накатан в `scripts/setup_rplidar_ros.sh` (см. memory: `rplidar_ros patch + setup script for Jetson cp210x workaround`).

### 6.3 udev-правило для стабильного имени

Чтобы устройство всегда было `/dev/zlac_chassis` независимо от порядка подключения, создать `/etc/udev/rules.d/99-zlac.rules`:

```
# ZLAC8015D RS-485 converter
SUBSYSTEM=="tty", ATTRS{idVendor}=="0403", ATTRS{idProduct}=="6001", ATTRS{serial}=="<SN_HERE>", SYMLINK+="zlac_chassis", MODE="0666"
```

Серийник конкретного экземпляра узнать командой:
```bash
udevadm info -a -n /dev/ttyUSB0 | grep '{serial}' | head -1
```

Если в проекте уже есть конвенция udev-правил по `KERNELS` (как для других ESP32/lidar) — следовать ей.

После добавления:
```bash
sudo udevadm control --reload-rules
sudo udevadm trigger
ls -l /dev/zlac_chassis
```

### 6.4 Low-latency mode (важно для Modbus)

FT232 по умолчанию буферизует пакеты до 16 мс перед отправкой в kernel — это убивает latency Modbus-запросов. Включить low-latency:

```bash
echo 1 | sudo tee /sys/bus/usb-serial/devices/ttyUSB0/latency_timer
```

Или удобнее — `setserial` / udev-правило с `ATTR{latency_timer}="1"`.

В постоянной форме — добавить в udev-правило выше:
```
SUBSYSTEM=="tty", ATTRS{idVendor}=="0403", ATTRS{idProduct}=="6001", ATTR{device/latency_timer}="1"
```

### 6.5 Отключить USB autosuspend

Чтобы Jetson не выключал USB-конвертер в простое:
```bash
echo on | sudo tee /sys/bus/usb/devices/<bus-id>/power/control
```

В постоянной форме — udev-правило:
```
ACTION=="add", SUBSYSTEM=="usb", ATTRS{idVendor}=="0403", ATTRS{idProduct}=="6001", ATTR{power/control}="on"
```

## 7. Проверка связи (bench-тест)

После сборки, перед интеграцией с ROS:

### 7.1 Низкоуровневый ping

```bash
sudo apt install python3-serial python3-pymodbus

python3 - <<'EOF'
import serial
s = serial.Serial('/dev/zlac_chassis', 115200, timeout=1)
print('open OK', s.is_open)
s.close()
EOF
```

### 7.2 Modbus-probe ZLAC8015D

```python
from pymodbus.client import ModbusSerialClient
c = ModbusSerialClient(port='/dev/zlac_chassis', baudrate=115200,
                      bytesize=8, parity='N', stopbits=1, timeout=0.2)
c.connect()
# Прочитать регистр версии прошивки (адрес из мануала ZLAC8015D, обычно 0x0000–0x0010)
r = c.read_holding_registers(address=0x0000, count=1, slave=1)
print('reply:', r.registers if not r.isError() else r)
c.close()
```

Ожидание: `reply: [<число версии>]`. Любая ошибка `ModbusIOException` или таймаут — проблема в железе:
- Перепутаны A/B (поменять местами).
- Не совпадает baud / parity (ZLAC обычно 115200/8N1, но в его прошивке настраивается, проверить через ServoStudio).
- Неверный slave-адрес (по умолчанию у ZLAC обычно `1`).
- Нет терминаторов → CRC-ошибки.

## 8. Известные проблемы и обходы

| Проблема | Симптом | Решение |
|---|---|---|
| Латентность 16 мс | Modbus-цикл медленный, ROS-узел не успевает 50 Гц | Low-latency mode (см. §6.4) |
| USB autosuspend | После простоя первый пакет долго идёт или теряется | `power/control = on` (см. §6.5) |
| CP210x dropping bytes на Jetson | Спорадические CRC-ошибки на холостых | Применить cp210x patch из `scripts/setup_rplidar_ros.sh` |
| Перепутаны A/B | Никакого ответа ни на какой запрос | Поменять провода местами на одной из сторон |
| Нет терминаторов | CRC-ошибки только на коротких пакетах или при высокой нагрузке | Включить terminate-перемычку на конвертере + 120 Ω на ZLAC |
| Не подключён GND | Спорадические CRC при движении робота, нет в покое | Протянуть третий провод GND вместе с витой парой |
| Помехи на старте моторов | Реконнект `/dev/ttyUSB0` каждый раз при разгоне | Изолированный конвертер + ферритовое кольцо на USB-кабеле |

## 9. Чек-лист валидации

- [ ] `dmesg` после подключения показывает FTDI или CP210x (НЕ CH340).
- [ ] `/dev/zlac_chassis` существует (udev-правило сработало).
- [ ] `latency_timer = 1` (cat `/sys/bus/usb-serial/devices/ttyUSB*/latency_timer`).
- [ ] `python3` открывает порт без ошибок.
- [ ] Modbus probe читает версию прошивки ZLAC8015D на slave=1.
- [ ] CRC-ошибок нет в течение 1 минуты непрерывного опроса (1000+ запросов).
- [ ] При включении силовой шины моторов и движении на холостых — CRC-ошибок по-прежнему нет.
- [ ] При резком ускорении/торможении мотор-каналов — `/dev/zlac_chassis` не пропадает из системы.
- [ ] `ros2 run verter_admin zlac_chassis_node` (когда реализован) держит связь без реконнектов в течение 10 минут teleop.

## 10. Итоговая рекомендация

**По умолчанию заказывать: Waveshare «USB TO RS485 (B)»** (с буквой B — изолированная версия). Это покрывает 95% сценариев при минимальной цене.

**Если робот идёт в production / эксплуатацию у заказчика:** Brainboxes US-320 или Moxa UPort 1130I.

**Один запасной экземпляр** держать на случай выхода из строя — конвертер копеечный по сравнению со временем простоя робота.
