# История BMS: хранение, графики и API

Окно `/battery-history` на порту мониторинга 8088 показывает все числовые значения
из BMS sample, каждую ячейку, разрешения заряда/разряда (0/1), код балансировки
и исходную битовую маску флагов. Текстовые поля протокола не являются измерениями.
Периоды: час, 6 часов, сутки, 3 дня, неделя. Обновление каждые 30 секунд.
Дополнительный SSH-порт не требуется. Интерфейс не отправляет команды управления.

## Сбор и сроки хранения

`verter-nats-bridge` записывает свежий снимок BMS раз в 10 секунд и дополнительно
при смене режима. Повтор одного sample_id не считается новым измерением.
Сбор работает при закрытом браузере. SQLite находится в
`<bridge.data_dir>/battery-history.sqlite` (штатно `data/nats-bridge/`).
WAL и операции в worker thread не блокируют asyncio-loop команд управления.
Сбой базы журналируется отдельно и не останавливает живые метрики.

Сохраняются время получения, sample_at, sample_id, charging_state и полный sample.
Время оси — Unix-время получения на Jetson; браузер показывает его в своей зоне.
Старые записи удаляются при записи раз в час; запросы всегда ограничены последними
604800 секундами. WAL повторно использует место; размер файла не обязательно
уменьшается после удаления строк. База сохраняется после перезапуска.
До включения сбора прошлых показаний нет; KV не позволяет восстановить неделю.
При выключенном bridge или отсутствии BLE измерения не восстанавливаются.

Режим определяется существующим правилом: ток > +0,1 A — charging,
ток < −0,1 A — discharging, иначе idle; устаревшие данные — unknown.
Статус не подтверждает подключение зарядного устройства или полный заряд.
Один режим не экстраполируется более чем на 15 секунд после наблюдения.

## NATS request/reply

Subject: `<robot_id>.battery.command.history`. Право публикации выдаётся локальному
client, подписки — backend; ответы через `_INBOX`. BMS publisher не получает новых
прав. Общий конверт v1, TTL до 30 секунд:

```json
{
  "v": 1,
  "id": "5beb6fa8-5b96-44fe-b191-f9a7935637a6",
  "issued_at": 1792163151,
  "ttl_s": 30,
  "args": {"period_s": 604800, "max_points": 240}
}
```

`issued_at` задаёт клиент текущим временем. В NATS-конверте action отсутствует:
действие закодировано subject. Для HTTP POST `/api/command` используется тот же
конверт с дополнительным `action: "battery.history"`.

Аргументы: `period_s` (0 < значение ≤ 604800, отсчёт от текущего времени Jetson),
либо `from`/`to` (Unix seconds, диапазон ≤ 7 дней, to по умолчанию now).
`period_s` нельзя смешивать с from/to. `max_points`: целое 20–360, по умолчанию 240.
Аргументы опциональны; без них возвращается неделя. Доступ к более старой истории
ограничен retention. Запросы не записываются в журнал команд и не меняют режим.

Ответ: обычный `{v,id,ok,at,result}`. При ошибке `{v,id,ok:false,at,error}`.
`result`:

- `from`, `to`, `bucket_s`: границы и ширина равных интервалов агрегации.
- `retention_s=604800`, `sample_interval_s=10`.
- `samples`: число исходных строк в диапазоне, включая неизвестное состояние.
- `available_from`, `available_to`, `stored_samples`: покрытие всей доступной недели.
- `point_fields=["at","mean","min","max","last"]`.
- `series`: словарь `<sample field>: [[at,mean,min,max,last], ...]`.
  Ячейки представлены как `cell_1_V`, `cell_2_V` и т. д. Булевы значения — 0/1,
  flags_raw — числовая битовая маска, без подтверждённого декодирования.
  at — центр временного интервала. Пустые интервалы отсутствуют, null не заменяется нулём.
- `states=["charging","discharging","idle","unknown"]`.
- `mode_seconds`: массив из max_points строк; каждая строка содержит длительности
  четырёх состояний в соответствующем интервале. Сумма равна bucket_s.
  Непокрытое наблюдениями время относится к unknown. Несколько режимов в одном
  интервале показываются долями, чтобы усреднение не скрывало заряд/разряд.

Линии показывают среднее по сохранённым наблюдениям, полоса — min/max.
Для флагов и кодов mean не следует трактовать как отдельное реальное состояние:
последнее фактическое значение выводится в подсказке. Короткие изменения между
снимками, кроме зарегистрированных смен режима, могут не попасть в архив.

## HTTP

`GET /api/battery/history?period_s=604800&max_points=240` — тот же NATS-запрос.
Также поддерживаются from/to. Неверные числовые параметры дают HTTP 400;
ошибки валидации backend — HTTP 200 с ok=false; недоступность NATS — HTTP 503.
Действуют текущие ограничения Host/Origin. Сторонние библиотеки/CDN не нужны.

Процент заряда (SOC) показан крупно над графиками; график SOC стоит первым,
затем напряжение, ток и остальные показатели, ячейки — после общих метрик.
Число сверху — последнее сохранённое значение выбранного периода.


## Экспорт CSV и TXT

Кнопки «Скачать CSV» и «Скачать TXT» выгружают выбранный в интерфейсе период.
В файле — исходные сохранённые наблюдения, без агрегации mean/min/max графиков.
Пустая история даёт файл с заголовком; неизвестные значения остаются пустыми.

`GET /api/battery/export?format=csv&period_s=604800` (или `format=txt`).
Вместо period_s можно передать from/to в Unix seconds; ограничения периода те же.
Формат CSV по умолчанию. Неизвестные параметры, неверные числа и формат дают HTTP 400.
Загрузка использует тот же порт 8088 и текущие проверки Host/Origin.

CSV: UTF-8 с BOM, разделитель запятая, десятичная точка, окончания строк CRLF.
TXT: UTF-8, разделитель табуляция, строки CRLF. Оба формата используют стандартное
CSV-экранирование: поля с разделителями, кавычками или переносами заключаются в кавычки.
При импорте в Excel выбрать UTF-8 и разделитель запятую (CSV) или табуляцию (TXT).

Первые столбцы: received_at_utc (ISO 8601 с Z), received_at_unix_s,
sample_at_utc, sample_at_unix_s, sample_id, charging_state.
Время received_at — запись на Jetson, sample_at — временная метка источника BMS.
Далее идут исходные поля BATTERY из contracts.py, protocol, flags_interpretation,
cell_1_V..cell_32_V и sample_json. Имена с _V/_A/_W/_Ah/_C задают единицы;
soc_pct — проценты, циклы/коды — безразмерные, булевы поля — 0/1.
Неподключённые ячейки пусты. sample_json сохраняет весь объект sample, включая
поля, для которых ещё нет отдельного столбца. flags_raw экспортируется исходной строкой.
charging_state: charging/discharging/idle/unknown. Для unknown без свежего sample
временная метка измерения и показания пусты; время записи сохраняется.

Экспорт читает NATS `<robot_id>.battery.command.history` порциями:
args `{ "from": ..., "to": ..., "raw": true, "limit": 250 }`.
Ответ result содержит from, to, raw=true,
row_fields=[received_at,sample_at,sample_id,charging_state,sample], rows (массив строк)
и next_after (временная метка последней строки или null в конце).
Следующий запрос повторяет фиксированные from/to и добавляет after=next_after;
курсор исключительный, поэтому строки не дублируются. limit: целое 1..250;
размер данных страницы дополнительно ограничен 512 КиБ. raw=false запрещён.
Без raw сохраняется прежняя агрегация графиков. Для raw нельзя задавать max_points.
Срок хранения 7 дней действует и при экспорте; новые записи после фиксированного to
не добавляются в уже начатую выгрузку. Ошибка до начала загрузки возвращает HTTP 400/503;
ошибка во время передачи прерывает файл, а не выдаёт успешный усечённый экспорт.
Новых NATS subjects и расширения прав управления нет.
